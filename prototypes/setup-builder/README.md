Throwaway, never merged. Answers [Step-by-step builder: what building a Setup feels like](https://github.com/afloret-services/AITradingBot/issues/76) on the map [Wayfinder: Setup builder, trade dashboard and 5-year backtest](https://github.com/afloret-services/AITradingBot/issues/63).

## Run it

```
cd prototypes/setup-builder
npm install
npm run dev          # http://127.0.0.1:5176/?variant=A&setup=silver_bullet
```

`npm run dev` first copies `mnq_1m.csv` (35 Trading days, 11 Sep – 29 Oct 2026, IBKR) from the `prototype/strategy-lab` branch into `public/data/`. The bars are git-ignored here and never committed (see [Remove the committed MNQ bar data from the public repo](https://github.com/afloret-services/AITradingBot/issues/82)).

## What's on the page

Four builders over one shared Setup model, switched with the floating bar at the bottom (or ← →):

- `?variant=A` **Wizard**: a fixed order of eight stages (general → indicators → when to trade → Signal steps → entry & Stop Loss → Trade settings → review & save → create a Run), with the overview and the chart only in Review & save (your call on the ticket: the editing stages stay uncluttered). Indicators are configured in their own stage and then picked. Steps are an accordion, and each step reads as a rule: **IF** a **AND** b **OR** c, then **THEN** … for the next step, ending in **→ SIGNAL** (the Entry). Each condition line has its own AND / OR; AND binds tighter than OR, so each run of ANDs is drawn as one box and the boxes are joined by OR. **ALL OF** and **ANY OF** groups (switchable from their header) group explicitly and nest. Underneath it is the same condition tree (an OR of ANDs). Run overrides use one row per section: Setup default / Override radio, then the same editor.
- `?variant=B` **Inline**: the Wizard without the Indicators & patterns step. In a step, **+ add** lists every pattern kind: picking one creates it with default settings and uses it there; its **settings** open in place. Any value can be an indicator, set up on the spot. Indicators and patterns no step uses any more are removed automatically. (Underneath, the Setup file still lists them once, so the engine and the hash are unchanged.)
- `?variant=C` **Lanes**: each branch is a horizontal lane, Step → Step → Entry → Trade, with the Sequence limits written on the connectors. A block library on the left inserts into the selected card and an inspector on the right edits it. Nesting is AND/OR chips. Settings sit in a toolbar. "Create a Run" mode locks the Signal cards and shows the Wizard's Create a Run in the inspector (instruments, then a Setup default / Override choice per section); picking a section on the Trade card scrolls to its row.
- `?variant=D` **Document**: the Setup is edited as its own Rule description, top to bottom, with every token a chip. Indicators are configured the first time a step reads them, and the sidebar lists them with labels and use counts. Nesting is an indented outline. Free text goes through a small phrase grammar ("15m close above EMA 200", "ADX(14) > 20", "MACD crosses above signal", "10:00-11:00"). Anything else gets a stubbed "Claude suggests" box to confirm. Run overrides are a diff table: default ↔ this Run, with Signal and In-position rules locked.

**Patterns, configured up front** (your answer on the ticket): FVG, Displacement, Order block, Leg and Market structure shift (MSS) are configured once per Setup, like indicators. Each has a name, a kind, a timeframe and its settings. A step then says "a bullish `fvg` forms" and reads what the pattern captured (`fvg.top`, `ob.bottom`, `mss.level`, `leg.start`…). The long and short branches share one configuration; only the side differs. Each pattern has two pictures: a schematic drawn from its kind and settings (it changes when you tick "middle candle is a Displacement" or "zone is the body"), and real occurrences found with those settings on the MNQ bars, which you can browse bullish or bearish. Renaming a pattern updates every step and token that reads it. Validation refuses an unconfigured pattern, a duplicate name or a timeframe finer than the Base bar, and warns about an unused pattern. In A it is a section of stage 2, "Indicators & patterns"; in B a sidebar card; in C a library group plus the settings inspector. Silver Bullet now configures `fvg` (1m, gap ≥ 4 ticks, middle candle a Displacement) and gives the same Signals as before.

**Kept level across the four designs** (the choice between them is still open): IF / AND / OR / THEN steps, the pattern palette with its categories and icons, indicator and Trade-settings icons, the Entry description, and every description. The Wizard shows the descriptions in full; the Document and Lanes, denser, put them behind "what this means" and "how steps work" toggles where the setting sits. The Document's session times are now editable too.

`?setup=silver_bullet | ema_macd | double_bottom | blank` picks the starting Setup. Both built Setups are the locked rules of #42, rebuilt from Rule blocks.

**Setup at a glance** (A and B: only in the Review & save step, with the chart under it; D: at the top): every branch as a flow, When → Step → Step → Entry → Trade. Each step card lists its conditions with a kind tag (pattern, compare, time, draw, preset), what it reads from earlier steps (`← fvg`) and what it captures (`→ draw`), and how often it completed on the bars. The connectors carry the Sequence limits ("same bar only", "within 3 bars", "until 11:00", "can be invalidated"). The Entry and Trade nodes summarise the order, stop, legs, Break-even, deadline, Flatten time and Signal guards, and each branch shows its Signals, Trades and total R. Hovering a configured indicator or pattern lights up the steps that read it; clicking a step opens it. C's lanes already are this view.

**The chart**: a legend with OHLC and every configured indicator's value under the crosshair; Trading hours shaded; only the focused step's completions as dots (all of them at once is noise). Clicking a Signal draws its pattern zones as boxes (FVG, Order block), an MSS as its broken level, a Leg as a line with its 50%, the Draw on liquidity, and the Trade as risk and reward areas with the legs. The Signal panel lists its events (each step's completion, the Signal, the fill, the exits) and replays them one at a time, hiding the bars that come after.

**Descriptions**: When to trade explains One at a time and the News rule, and every Trade-settings section (and In-position rules) explains what it does and then works it through with the Setup's own numbers (for example $5000 × 3% = $150, so a 20-point MNQ stop trades 3 contracts).

Common to all three: a live chart (TradingView Lightweight Charts) on the Base bar, with each step's completions as coloured dots, the focused step's "held alone" bars as grey squares, Signals with a rough Trade result, and the selected Signal's entry, stop, legs and draw. Also common: Draft save with warnings, Freeze → v1 (SHA-256 over what the engine reads, refused on errors or on an identical hash), Export file, a JSON view, and "duplicate as mirrored short".

## The evaluator in `src/engine.ts`

A rough evaluator, not the engine. It exists so each step shows its effect on real bars. On these bars it already reproduces `prototype/strategy-lab`:

- **Silver Bullet** (preset B): the long Signals exactly. With "duplicate as mirrored short", 2 of 3 short Signals; the extra one (10-19 10:44) wasn't chased.
- **EMA 200 + MACD** (all sessions to 16:00): 15 of 16 Signals with the same time, stop and refusal reason. The 16th (09-28 long, 20:00) is lost because Candidates end at the Trading day's end.

## What building them surfaced (for the spec and for "Evaluator on real bars")

1. **Mirroring needs to know magnitudes.** "Duplicate as mirrored short" first flipped `≥` to `≤` on range and body %, so the short Displacement asked for a small candle. Directional values (prices, levels, MACD against 0) flip. Magnitudes (range, body, body %, volume, ADX, ATR, average range, sizes, Trade R values) keep their operator. Upper and lower wick swap, and RSI mirrors around 50.
2. **In-position rules belong to a branch.** The long "close below the EMA 200" exit closed shorts too. Mirroring a branch must also mirror its In-position rules.
3. **A running capture must be able to start where a "For at least N bars" run began.** EMA 200 + MACD's pullback low covers the whole negative-histogram run, not just the bar where the step completed.
4. **A first step that keeps holding needs "ignore", not "replace".** Otherwise each bar restarts the Candidate and its running capture. Pair "ignore" with an invalidation (the histogram had turned last bar).
5. **Trading-day expiry of Candidates loses EMA 200 + MACD Signals** whose pullback spans 18:00. This needs a per-Setup (or per-step) "keeps across the Trading-day start" option.
6. **Guard order:** the stop-width Signal guard is checked before sizing, so the refusal reason matches the lab's.

## Decided so far (your answers while trying it)

- **Backtest Run on this Draft, in Review & save** (2026-11-26, [ADR 0007](https://github.com/afloret-services/AITradingBot/blob/ccr-2faecedc-9t16ly/docs/adr/0007-draft-backtest-runs-build-years-only-never-read-by-the-gate.md)): pick instruments by type and create a backtest Run that binds the Draft; a table (cards when narrow) shows Signals, refused (with the main reason), Trades, win rate, total R, $ result, max drawdown in R and contracts a Trade, plus each instrument's warnings (hours, volume). It runs on the build years only (the held-out last 12 months stay locked), is listed with the Runs marked Draft (latest per instrument kept, plus pinned ones), and is never promoted or read by the gate. In the prototype only MNQ has bars; NQ replays them at $20 a point (same Nasdaq-100 prices), the rest show "no numbers".
- **Stocks and options join the instruments** (2026-11-26). Create a Run picks the instrument by type first: Futures (MNQ, MES, NQ, ES; M6E), Forex (EUR/USD, GBP/USD, USD/JPY spot), Stocks (SPY, QQQ; AAPL, NVDA, TSLA), Options (on the same names, with an expiry: 0DTE / nearest weekly / nearest monthly, and a strike: at the money / 1 strike out of the money / delta about 0.30). A long branch buys calls, a short branch buys puts; the Setup still reads the underlying's chart. Stocks and options trade 09:30–16:00 New York, so a Trading window outside it is flagged. The prototype has bars for MNQ only and does not price options.
- **Instruments are a multi-select** (2026-11-27), in Create a Run and in the backtest Run on this Draft: the picked instruments show as tags in category order, the list is grouped Futures / Forex / Stocks / Options with a filter and Select all per category, and each picked option gets its expiry and strike. A Run binds the Setup version once per picked instrument, all with the same overrides.
- **Instrument search for a bigger list** (settled 2026-11-27): one search across every category (symbols first, then names), tabs All / Futures / Forex / Stocks / Options with counts, Recent and Instrument lists before typing, the first 5 per category in All with "Show all N", 25 rows at a time in a tab, rows without 5 years of history greyed out with the reason, and tags collapsing after 8 ("+N more"). The catalog (16 futures, 20 forex pairs, 61 stocks and ETFs, options on the same 61) and five built-in Instrument lists are made up, and come from `src/instrumentManagement.ts`, a stand-in for an Instrument management module that manages Instruments and Instrument lists; a list shows how many of its instruments it skips for lack of history.
- **Backtest results per instrument** (2026-11-27, replaces "What it did on MNQ"): the backtest Run on this Draft takes a period: Last 30 days, Last 3 months (default), Last 6 months, Last year, 2, 3 or 4 years, counted back from the end of the build years, or Custom dates (two date pickers); "5 years" shows locked, because a Draft never sees the held-out last 12 months (ADR 0007), and a "Backtest results" card shows one instrument at a time: Trades (with Signals and refused), win rate (won and lost), average R per Trade, capital growth in % and $ of the Setup's capital, and the average, max and min drawdown in % and $ (a drawdown runs from a high of the account to its next new high, in % of that high). Its chart stays inside the period and shows each Signal's steps, entry, Stop Loss, Take Profits and exits; the Trades list (date, side, entry, Stop Loss, Take Profits, exit, R, $, capital, drawdown after the Trade) shows a Trade on the chart when clicked. Shared state: `useDraftBacktest` in `TrialBacktest.tsx`; view: `BacktestResults.tsx`.
- **Break-even shown** (2026-11-28): the engine records each Stop Loss move (`TradeResult.stopMoves`, plus the real `fillPx`); on the chart the risk box ends where the Stop Loss moved, then a dashed amber "BE" line runs at the new stop, with a BE marker, a BE price-axis label and a replay step "Stop Loss moved to … · break-even after TP1 / at +X R"; the exit reads "stop at break-even". In the results, a Trade whose Stop Loss moved carries a BE badge, and one that closed at its break-even stop with nothing banked counts as break-even, neither won nor lost ("2 won · 5 lost · 4 break-even · 6 went to break-even"). The presets never reach break-even on the sample; set Double bottom's Break-even to "+0.5 R" to see it.
- **Costs, sample size, equity curve, profit factor** (2026-11-28): the results switch between After costs (default) and Before costs; costs come per Instrument from Instrument management (`instrumentManagement.costs(id)`, made up: MNQ $0.62 a contract each side, 1 tick slippage on market and stop fills, never on resting limits or Take Profit fills) and come off every R and $; a Costs column in the Trades list. Under 30 Trades an amber note says the sample is too small to judge. A Profit factor tile ($ won ÷ $ lost) with average win and average loss in R; Average R is the expectancy. An equity curve (SVG) of the account after each Trade, its running high dashed and the drawdowns shaded, each point clickable to show that Trade.
- The protective stop is called **Stop Loss** everywhere (the "Entry & Stop Loss" step, its editor, the summaries, the Rule description, refusal reasons). "Stop entry" keeps its name: it is the order type that fills on a break through a price.
- Stop Loss "Measured from": a level (a low, a pattern edge…; the default), the entry price (N ticks or × ATR from it), or a fixed $ a contract from the entry. Below / above stays set by the branch side (long below, short above), not a free choice.
- Losing streak (new Trade-settings section, per Setup, a Run may override it): after N losing Trades in a row on one Trading day, across both branches, the Setup stops for the rest of that day; the next Trading day it resumes at a set % of its contracts (never below 1) until its first winning Trade. Off by default. The Run's account-wide daily loss limit (Stand-down) still applies on top.
- Patterns are configured up front, like indicators, then used by name in steps.
- In the Wizard, the Setup at a glance and the chart appear only in Review & save.
- Chart patterns (double top / bottom, triple top / bottom, head and shoulders and its inverse; triangles ascending / descending / symmetrical, rising and falling wedges, bull and bear flags and pennants, rectangles, rising and falling channels; broadening formation / megaphone, ascending and descending broadening wedges, cup and handle and its inverse, diamond top / bottom, rounding top / bottom, island reversals, bump-and-run reversals, measured move up / down, parabolic blow-off / capitulation, Wyckoff accumulation / distribution and re-accumulation / re-distribution; Adam & Eve double top / bottom and the complex head and shoulders) are pattern kinds like the ICT ones: configured once, used by name, the side picks top or bottom; reversal patterns form on the first close through the neckline, triangles, wedges, flags, pennants, rectangles and channels on the first close through their boundary line in the side's direction; each captures its line, height (or pole) and measured-move target. Starter "Double bottom (chart-pattern demo)" trades one.
- Candlestick patterns are pattern kinds too: engulfing, hammer / shooting star, morning / evening star, harami, piercing line / dark cloud cover, three white soldiers / three black crows, tweezer bottom / top, inside-bar breakout, doji (after a drop or a rise; optionally dragonfly / gravestone only) and marubozu. The side picks the bullish or bearish one; most have an optional "after a move against it over N bars" filter; they form on the close of their last candle and capture its high, low, open, close and mid.
- Pattern categories: Type (Continuation / Reversal / Indeterminate), Bias (Bullish / Bearish / Neutral) and Classical / Lesser-Known, with Consolidation and Typically breaks. The configure palette filters by them and each pattern shows them; candlesticks, which that page does not cover, use the usual reading.
- "One at a time" is called Trade overlap: Allow overlap / Wait for the Trade to end / Skip Signals during the Trade.
- "Trading hours" is called Trading window.
- "Sessions" are called Market sessions.
- While in a Trade (was In-position rules): "If … at a bar close, then Close the whole Trade / Close TP k now / Tighten the Stop Loss / Cancel the waiting entry"; "+ Add a rule".
- Take Profits: "At a multiple of the risk (R)" / "Just before a level" / "Part of the way to a level"; "close N % of the contracts"; "Extra contracts go to TP1 first / the last TP".
- Stop Loss: "Place the Stop Loss [N] [ticks | × ATR using ATR] below [level]" ("above" on a short branch), badge "required".
- Risk per Trade fields: Account size ($) / Risk each Trade (% of account) / At most N contracts.
- "Expiry and Flatten time" is called Closing time: "Close open Trades at (optional)" and "Be flat by (required)".
- Signal guards: "Skip if the Stop Loss is wider than N ticks / × ATR" and "Skip if the reward is under N × the risk", added with "+ Stop Loss too wide" / "+ Reward too small".
- Break-even options: Never / After TP k fills / Once price is +X R in profit; the offset is "lock in N ticks".
- Entry deadline options: Wait until a set time (NY) / Wait N Base bars / Wait until the Trading window closes / Wait until the Trading day ends; "Cancel if price reaches first: the Stop Loss / TP1 / the Draw".
- "News rule" is called News filter: Trade through the news / Skip the whole News day / Skip around each release.
- The Leg pattern is called Swing (an up swing / a down swing, captured as swing.start, swing.end…), and the measured move's legs are its first and second swing (captured as mm.swing).
- "Take Profits" replaces "Take Profit legs": the section is Take Profits, each one TP1, TP2… (your call while trying it; the glossary term "Take Profit legs" would change with it).
- Signal steps read as rules: IF … AND/OR …, THEN … for the next step, ending in the Signal. AND is checked before OR; ALL OF / ANY OF groups group explicitly (they replaced ( … ) brackets).
