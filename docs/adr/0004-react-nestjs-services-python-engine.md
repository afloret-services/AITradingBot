# React UI, NestJS services in hexagonal shape, Python engine

The builder, the dashboards and every other screen are React on an existing open design system (shadcn/ui on Tailwind), with charts on TradingView Lightweight Charts. Every API is a NestJS service built as ports and adapters. The engine stays one Python process doing everything at bar speed (bars, the Rule-block evaluator, Signal filter, risk guard, Trade manager, IBKR adapter), so the evaluator is the same code in a backtest Run and a paper Run; the services own everything around it (Setups and their versions, Runs, backtest jobs, the Promotion gate, the feeds for the dashboard and the chart review). NestJS was chosen over Go so the Rule-block schema and its types are shared with the React builder. This replaces the "one Python process with a self-contained HTML review page" shape of [Spec: multi-Setup paper-trading bot on IBKR (MNQ), first paper version](https://github.com/afloret-services/AITradingBot/issues/42).
